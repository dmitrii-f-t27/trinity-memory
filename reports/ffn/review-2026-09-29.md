# FFN oracle contract correction

Result date: 2026-09-29 UTC. Refs #91; included in PR #90.

## Corrected behavior

Both RMSNorm paths now use `sqrt(mean(x*x) + epsilon)`. The original PR used
`max(sqrt(mean(x*x)), epsilon)` in the f64 reference and fixed-point datapath.
For a constant 1e-6 input and a unit norm weight, the original returned 0.1;
the upstream formula returns 0.0003162277502054508. Testing only the previous
large input hid the discrepancy.

The relu2 product now saturates to signed 64-bit and records each saturation.
The original synthetic stress case produced 151115727240722414403584, beyond
the signed maximum 9223372036854775807, while reporting zero saturations.
Both positive and negative saturation now have regression coverage.

The worst-case sum of 6912 squared signed 64-bit values is
`6912 * 2**126`. Its integer bit length is 139, so the former claim that a
128-bit accumulator covers the entire declared input range is removed.
The Python oracle uses arbitrary-precision norm intermediates; RTL widths and
hardware implementation remain separate work.

## Validation

- Three new regression tests failed on a47ffbc before the fix.
- All 10 FFN tests passed after the fix, including the real layer replay;
  `TRINITY_REQUIRE_CACHED=1` was set and no tests skipped.
- Nine required fixture ranges were anonymously fetched: 14,338,566 bytes,
  each checked against the manifest SHA-256 before use.
- The committed seed-27 report was regenerated. All six stages pass the
  existing error guard; all saturation counts are zero on this real input.
  Stage h is exact after Q16.16 conversion. Stage y has a maximum error of
  350 Q16.16 units against a peak of 72,883,440 (350 / 72,883,440, approximately
  4.80e-6 of peak). This is not a bound on relative error near zero.
- The fixture-backed test now compares every stage, both output hashes,
  saturation counts, and contract metadata. It runs in the cached
  `ternary-check` CI job with missing fixtures treated as a failure.
- Manifest consumer attribution includes every FFN input, not just the four
  newly added ranges. The manifest lock regenerated without a byte-range change.
- Local decoding used the SHA-256-verified macOS arm64 v0.5.0 release runtime
  (wheel SHA-256 5d42556c4f088dffaaa1eca31d2273b42a3e8685821614ac2054ad316dfcfa38).
  The relevant `t27/formats.t27`, `t27/matvec.t27`, and `native/core.c` sources
  are unchanged from that tag. No local native rebuild is claimed.

Reproduce with a matching generated native runtime and the manifest cache:

```text
TRINITY_FIXTURES_OFFLINE=1 TRINITY_REQUIRE_CACHED=1 python3 -m unittest tests.test_ffn_reference -v
TRINITY_FIXTURES_OFFLINE=1 python3 tools/ffn_reference.py --json reports/ffn/reference-2026-09-28.json
```

## Scope and primary sources

This is a reference for unquantized-activation FFN math and a candidate
fixed-point arithmetic contract. It does not replay AutoBitLinear ActQuant,
bf16 runtime rounding, attention, residuals, or a complete model, and it is not
a board measurement. The report now carries this scope explicitly.
