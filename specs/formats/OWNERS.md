# OWNERS — specs/formats/

## Primary

**Trinity Memory** (`dmitrii-f-t27/trinity-memory`, shared project of Dmitrii Fedorov and
Dmitrii Vasilev) — byte-level contracts for the public ternary weight-packing formats that
t27 Ternary Check reads and writes. Roadmap: [epic #27](https://github.com/dmitrii-f-t27/trinity-memory/issues/27),
[issue #29](https://github.com/dmitrii-f-t27/trinity-memory/issues/29).

| Spec | Module | Formats | Upstream (commit in `upstream.lock.json`) |
|---|---|---|---|
| `llama_cpp.t27` | `TrinityFormatsLlamaCppSpec` | TQ1_0, TQ2_0, Q2_0 (group 64), Q1_0; GGUF tensor rules and the type-id rule | ggml-org/llama.cpp `e6ab7c1a` |
| `prismml.t27` | `TrinityFormatsPrismmlSpec` | PQ2_0, PTQ1_0, the fork's Q2_0 (still group 64) | PrismML-Eng/llama.cpp `bdc23b56` (branch `prism`) |
| `bitnet_cpp.t27` | `TrinityFormatsBitnetCppSpec` | I2_S (x86 ACT_PARALLEL), ARM and four-row layouts as negative cases | microsoft/BitNet `0b341e58`, submodule isHuangXin/llama.cpp `390c3077` |
| `hf_bitnet.t27` | `TrinityFormatsHfBitnetSpec` | packed uint8 weights and `weight_scale` | huggingface/transformers `2c4914fb` |
| `mlx.t27` | `TrinityFormatsMlxSpec` | 2-bit affine codes, scales, biases | ml-explore/mlx `59d600b5` |
| `onnx.t27` | `TrinityFormatsOnnxSpec` | `com.microsoft.MatMulNBits`, `bits=2`, packed zero points | microsoft/onnxruntime `2ecddca3` |

Each spec's header restates the upstream commit and the `file:line` ranges it follows.
`upstream.lock.json` (schema `trinity.upstream-pins.v1`) records, per upstream, the repository,
branch, full commit and the git blob SHA of every cited file.

## Dependencies

- The compiler pinned by `native/compiler.lock` (`gHashTag/t27`).
- The implementation `t27/formats.t27` (module `TrinityMemoryFormats`, prefix `tf_`/`TF_`).
  Specs restate contracts and are tied to the implementation by the differential harness
  `tests/native_spec_formats.c`; they never replace it.

## Generates

- `build/t27/specs/<name>.h` (C with `_Static_assert` invariants and an executed test runner)
  and `build/t27/specs/<name>.v` (Verilog syntax gate), both from `tools/check-specs.sh`.
- Seals in `.trinity/seals/formats_<Module>.json` (`t27c seal --save specs/formats/<file>.t27`
  from the repository root).
- Vectors in `conformance/formats_<family>.json`, generated by `tools/generate-spec-vectors.py`
  (the family is the spec's file name). `tools/check-specs.sh` fails when a spec under
  `specs/formats/` has no vectors file naming it, when no `tests/native_spec_*.c` includes
  its header, or when no harness prints `replayed conformance/formats_<family>.json: N vectors`.

## Status classes

Every reader in `t27/formats.t27` either rejects its input with a negative status or accepts
it and reports conditions in flag slots. The tokens below are shared by the vectors
(`constants.errors`, `constants.flags`, `error_class`) and by the CLI contract of issue #36.

Reject classes (the reader returns the status and writes no output):

| Token | Status | Raised when | Upstream behaviour |
|---|---|---|---|
| `format` | -50 | unknown format id | — |
| `length` | -51 | weight count not whole blocks, byte size not the count's size, a shape the format cannot store (HF rows % 4, MLX group, ONNX block size), GGUF row not whole blocks | llama.cpp (`gguf.cpp`, `ggml_validate_row_data`) and MLX (`affine_quantize`, `affine_dequantize`) reject |
| `capacity` | -52 | caller's output buffer too small | — |
| `code` | -53 | an encoder is given a value outside the format's code table | — |
| `padding` | -54 | reserved; no format reader returns it (nonzero padding is the flag `padding_nonzero`) | — |
| `truncated` | -55 | container prefix too short (`needed` says how much to read) | — |
| `container` | -56 | malformed GGUF or safetensors header | `gguf.cpp` rejects |
| `not_found` | -57 | tensor name not in the container | — |
| `scale_nonfinite` | -58 | NaN or infinity in a block scale, the I2_S scale, `weight_scale`, an MLX scale or bias, an ONNX scale | llama.cpp rejects NaN/Inf `d` only with `--check-tensors`; the other readers cited here do not check scales |
| `type_ambiguous` | -59 | a GGUF type id whose meaning differs between two namespaces marked in the same file | — |
| `layout_unsupported` | -60 | a GGUF type id that names TL1 or TL2 | bitnet.cpp decodes with its generated kernels |
| `misaligned` | -61 | a GGUF tensor offset not a multiple of `general.alignment` | `gguf.cpp` rejects (offsets must equal the padded end of the previous tensor) |
| `extent` | -62 | a GGUF tensor's bytes run past the next tensor's offset | `gguf.cpp` rejects |

Flag classes (decoding succeeds, values are unchanged, the count is reported):

| Token | Slot | Counts | Upstream behaviour |
|---|---|---|---|
| `outside_ternary` | 0 | weights whose value is outside {-1, 0, +1}: 2-bit code 3 (+2) in TQ2_0, Q2_0, PQ2_0, I2_S, HF packed, MLX; ONNX code minus zero point outside ±1 (code 0 under the default zero point 2 is -2) | decoded as ±2 (I2_S: undefined; the x86 kernel multiplies the raw code) |
| `noncanonical_base3` | 1 | TQ1_0/PTQ1_0 bytes the quantizer never writes (13 of 256 `qs` values, 175 of 256 `qh` values) | decoded like a canonical byte |
| `scale_negative` | 2 | finite scales with the sign bit set (per block, per tensor or per group) | decoded with flipped signs |
| `scale_zero` | 3 | scales equal to ±0 | every weight of the group decodes to 0 |
| `trailer_nonzero` | 4 | nonzero bytes among the 28 I2_S trailer bytes after the scale | never read |
| `padding_nonzero` | 5 | nonzero ONNX codes at k ≥ K in a row's last block | never read |
| `affine_not_ternary` | 6 | MLX groups whose bias is not -scale | decoded as affine values |

Silent cases (neither class can see them; the vectors record the silent output):

| Token | Case | Why the reader cannot tell |
|---|---|---|
| `group_size_mismatch` | group-128 bytes (PQ2_0) read as group-64 Q2_0 | 306 bytes are 9 PQ2_0 blocks and 17 Q2_0 blocks; every byte is a valid code. This is a synthetic case: the published Q2_0 file holds valid group-64 blocks. In a GGUF file the `extent` check catches it unless the tensor is the last one. |
| `i2s_layout_arm` | bytes written by bitnet.cpp's ARM build read as ACT_PARALLEL | the same n/4 + 32 bytes, other weight positions |
| `i2s_layout_1x4` | bytes written by bitnet.cpp's x86 build without ACT_PARALLEL read as ACT_PARALLEL | as above |
| `q1_0_payload` | a corrupted Q1_0 byte | every bit pattern is a valid pair of ±1 values |

## GGUF type ids

Type ids collide across the three namespaces this repository reads. A file is marked as
PrismML when a key begins with `prism.`, and as bitnet.cpp when `general.architecture` is
`bitnet-b1.58` (an architecture only bitnet.cpp's llama.cpp defines) or a tensor has type
36 or 38. `tf_format_of_gguf` and `tfs_llama_gguf_format` apply:

| Id | ggml-org | PrismML | bitnet.cpp | Reader |
|---|---|---|---|---|
| 34, 35, 41 | TQ1_0, TQ2_0, Q1_0 | same | same | that format |
| 36 | removed | removed | I2_S | I2_S when marked bitnet.cpp |
| 38 | removed | removed | TL1 | `layout_unsupported` when marked bitnet.cpp |
| 42 | Q2_0 (group 64) | Q2_0 (group 64) | TL2 | Q2_0, or `layout_unsupported` when marked bitnet.cpp |
| 142, 143 | invalid | PQ2_0, PTQ1_0 | invalid | that format when marked PrismML |
| 36, 38, 42, 142, 143 | | | | `type_ambiguous` when marked both PrismML and bitnet.cpp |

A bitnet.cpp TL2 file without either marker (for example architecture `llama`) is read as
Q2_0. TL2 stores about 5/24 byte per weight (bitnet.cpp's `ggml.c:1314-1321`), Q2_0 9/32, so
for weight matrices of real models (many rows of at least 512 weights) a TL2 tensor is
shorter than its Q2_0 reading and `extent` rejects it, except the last tensor in offset
order.

## Bits per weight

"Bits per weight" counts the stored tensor bytes: codes, scales, zero points, biases and
format-internal padding (I2_S tail, ONNX block padding). The metadata share is counted
separately: for a GGUF tensor it is its info record (24 bytes + name + 8 bytes per
dimension) plus the alignment padding after its data (`tfs_llama_gguf_tensor_bits`); the
GGUF header and key-value section, and the safetensors JSON header, belong to the whole
file and are reported as file overhead, not per tensor.

| Format | Block | Bytes | Bits per weight |
|---|---|---|---|
| TQ1_0 | 256 | 54 | 27/16 = 1.6875 |
| TQ2_0 | 256 | 66 | 33/16 = 2.0625 |
| Q2_0 | 64 | 18 | 9/4 = 2.25 |
| Q1_0 | 128 | 18 | 9/8 = 1.125 (binary, ±1) |
| PQ2_0 | 128 | 34 | 17/8 = 2.125 |
| PTQ1_0 | 128 | 28 | 7/4 = 1.75 |
| I2_S | 128 (tensor) | n/4 + 32 | 2 + 256/n |
| HF packed | tensor | rows/4 × cols + scale | 2 + 16/n (bf16 `weight_scale`) |
| MLX 2-bit | group g | g/4 + 4 per group | 2 + 32/g (9/4 at g = 128) |
| ONNX bits=2 | block b | b/4 per block + scale (+ zero points) | 2 + s/b (+ 2/b), e.g. 17/8 at b = 128, f16 |

The invariants state these as integer ratios; the test blocks compute them for real tensor
shapes (BitNet b1.58 2B4T `blk.0.ffn_down`, Ternary Bonsai 2 27B `blk.0.ffn_down`).

## Out of scope

- **STQ1_0**: proposed in the open llama.cpp pull request #22836 (not merged on 2026-09-23).
  It has no type id on the upstream default branch and its layout can change before a
  merge, so there is no commit to pin a contract to.
- **TL1 and TL2** (bitnet.cpp): lookup-table layouts whose byte order depends on tile sizes
  that `utils/convert-hf-to-gguf-bitnet.py:469-522` reads from the build's
  `include/kernel_config.ini` for each weight shape; the GGUF file does not record them.
  Without a self-describing storage contract the reader rejects both ids as
  `layout_unsupported`.
- ONNX Runtime floating-point (unpacked) zero points, `bits` other than 2, and MLX `bits`
  other than 2.

## Conventions

- Header: SPDX line, `specs/formats/<file>.t27 -- <purpose>`, the upstream repository with its
  full commit and the `file:line` ranges restated, then `phi^2 + 1/phi^2 = 3 | TRINITY`.
- Names: `pub const TFS_<FAMILY>_*`, functions `tfs_<family>_*` (`LLAMA`, `PRISM`, `BITNET`,
  `HF`, `MLX`, `ONNX`), one brace-form `module` per file. Test titles begin with the family,
  because every test becomes a global C function and the harness includes all six headers.
  File names must not repeat a basename under `specs/` (headers are flattened by basename).
- Status and flag values equal the implementation's `TF_ERR_*` and `TF_FLAG_*`; the harness
  asserts it.
- Reference functions take scalars and slices only: struct pointers fail the Verilog gate.
  Array literals belong in test blocks only (inside functions they are not lowered to
  Verilog). Constants are untyped `#define`s, so an `assert` must not begin with `(`.
- Every change to a spec: rerun `tools/check-specs.sh`, reseal from the repository root
  (`t27c seal --save specs/formats/<file>.t27`, never `--force`), regenerate the vectors with
  `python3 tools/generate-spec-vectors.py`, and keep `tests/native_spec_formats.c`,
  `tests/spec_formats_wasm_replay.mjs` and `tests/test_spec_formats.py` passing.
